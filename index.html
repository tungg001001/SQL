SQL Injection（SQL 注入攻擊）完整教學導覽

本導覽涵蓋 SQL 注入的核心成因、攻擊類型、進階危害與防禦實踐。內容嚴謹對應線上測驗之核心觀念，協助全方位建立安全的網頁應用程式開發思維。

一、SQL 注入核心成因與基本語法 (考點對應: Q1, Q3, Q4, Q8)

❌ 漏洞根源：動態字串拼接

當後端直接以字串組裝使用者輸入時，攻擊者可輸入單引號 ' 破壞字串邊界，並帶入 OR '1'='1 使 WHERE 條件永遠成立，實現**身分驗證繞過**。

SELECT * FROM users WHERE user = '' OR '1'='1'

🔑 關鍵語法與端點防禦認知

  • 註解符號 --： 在標準 SQL 中代表單行註解，可將其後方的原查詢條件（如密碼比對）完全忽略。
  • 前端 JavaScript 驗證限制： 單靠前端過濾無效！攻擊者可輕鬆繞過瀏覽器（如使用 Postman 或 Burp Suite）直接發送封包至後端。

二、進階攻擊手法與極限危害 (考點對應: Q5, Q6, Q11, Q13, Q16)

UNION 聯合查詢

透過 UNION SELECT 跨表擷取資料。嚴格限制： UNION 兩側的查詢必須具備**相同的欄位數量**且**對應位置資料型態相容**。

盲注 (Blind SQLi)

當系統不直接回傳資料庫錯誤或結果時，透過 **布林盲注** (判斷 True/False) 或 **時間盲注** (使用 SLEEP() 函數引起回應延遲) 推斷資料。

DBA 特權與 RCE 危害

若資料庫連線帳號具備 DBA 或 root 高特權，攻擊者可能透過讀寫系統檔案執行作業系統指令，導致**伺服器全面淪陷 (RCE)**。

三、防禦架構與縱深防禦實踐 (考點對應: Q2, Q7, Q9, Q10, Q14, Q15, Q17, Q18)

✅ 參數化查詢 (Prepared Statements) 與 ORM

將 SQL 語法先預編譯，隨後傳入的變數皆被當作純**資料值 (Literal Value)** 處理。即便輸入含 ' OR '1'='1，資料庫也只會精確比對字面相符的字串。成熟 ORM (如 Prisma, SQLAlchemy) 預設即採用此機制。

🛡️ 特殊情境防禦與縱深防護

  • ORDER BY 防禦： 動態排序無法使用傳統參數化綁定，必須採用**白名單 (Whitelist)** 機制進行檢查。
  • 最小權限原則： 限制 DB 帳號權限，就算遭突破也能將損害控制在最小範圍（備份為災難復原，非防範漏洞手法）。
  • WAF (Web 應用程式防火牆)： 作為邊緣輔助防護層阻擋常見攻擊，但**無法替代安全的後端程式碼**。

主流程式語言安全防禦語法示範

以下範例說明如何在常見開發語言中全面採用「參數化查詢 (Prepared Statements)」。

使用 sqlite3 或 psycopg2，透過 ? 或 %s 占位符將變數以 Tuple 傳入 (對應 Q17)：

# ✅ 安全：將使用者變數透過 Tuple 綁定
cursor.execute("SELECT * FROM users WHERE username = ? AND password = ?", (username, password))
user = cursor.fetchone()

使用 mysql2 套件時，使用 ? 陣列傳參：

// ✅ 安全：使用 execute 方法與預處理陣列
const [rows] = await connection.execute(
  'SELECT * FROM users WHERE username = ? AND password = ?',
  [userInputUsername, userInputPassword]
);

使用 PDO 物件導向預處理 (對應 Q12)：

<?php
// ✅ 安全：使用 prepare 與 execute 分離資料
$stmt = $pdo->prepare('SELECT * FROM users WHERE username = :user AND password = :pass');
$stmt->execute(['user' => $userInputUsername, 'pass' => $userInputPassword]);
$user = $stmt->fetch();
?>

使用 JDBC 的 PreparedStatement：

// ✅ 安全：綁定參數
String sql = "SELECT * FROM users WHERE username = ? AND password = ?";
PreparedStatement stmt = connection.prepareStatement(sql);
stmt.setString(1, userInputUsername);
stmt.setString(2, userInputPassword);
ResultSet rs = stmt.executeQuery();
