什麼是 SQL Injection（SQL 注入攻擊）？

SQL Injection 發生在當應用程式將「使用者輸入的資料」未經妥善過濾，就直接與「SQL 資料庫查詢指令」進行字串拼接時。攻擊者藉由輸入惡意 SQL 語法，破壞原有的查詢結構，從而存取、修改或刪除資料庫中的資料。

漏洞示範

❌ 不安全的作法：動態字串拼接

將使用者傳入的變數直推拼接到 SQL 指令中，使輸入變成指令的一部分。

SELECT * FROM users 
WHERE username = '' OR '1'='1' 
AND password = '...';
風險： 輸入 ' OR '1'='1 會破壞邏輯判斷，因為 '1'='1' 永遠為真，可直接繞過密碼驗證！
安全標準

✅ 正確的防禦：參數化查詢 (Prepared Statement)

將「指令結構」與「資料內容」完全分離，資料庫會將傳入變數純粹當作資料處理。

SELECT * FROM users 
WHERE username = ? 
AND password = ?;
效益： 即使輸入包含 ' OR '1'='1，資料庫也會精確比對使用者名稱是否「字面等於」該字串，不會執行注入邏輯。

主流程式語言參數化查詢 (Prepared Statements) 範例

防止 SQL Injection 最有效的方式即是在後端程式碼中全面採用參數化查詢。

使用 sqlite3 或 psycopg2 時，使用 ? 或 %s 占位符傳入參數 Tuple：

import sqlite3

conn = sqlite3.connect('database.db')
cursor = conn.cursor()

# ✅ 安全：將參數放入 Tuple 傳遞給 execute 方法
username = user_input
password = pass_input

cursor.execute("SELECT * FROM users WHERE username = ? AND password = ?", (username, password))
user = cursor.fetchone()

使用 mysql2 套件時，傳入帶有 ? 占位符與陣列參數：

const mysql = require('mysql2/promise');
const connection = await mysql.createConnection({/* config */});

// ✅ 安全：使用 execute 預處理查詢
const [rows] = await connection.execute(
  'SELECT * FROM users WHERE username = ? AND password = ?',
  [userInputUsername, userInputPassword]
);

使用 PDO 延伸套件進行預編譯與綁定：

<?php
$stmt = $pdo->prepare('SELECT * FROM users WHERE username = :username AND password = :password');

// ✅ 安全：綁定參數
$stmt->execute([
    'username' => $userInputUsername,
    'password' => $userInputPassword
]);
$user = $stmt->fetch();
?>

使用 JDBC 的 PreparedStatement：

String sql = "SELECT * FROM users WHERE username = ? AND password = ?";
PreparedStatement stmt = connection.prepareStatement(sql);

// ✅ 安全：設定欄位參數
stmt.setString(1, userInputUsername);
stmt.setString(2, userInputPassword);
ResultSet rs = stmt.executeQuery();
