什麼是 SQL Injection (SQL 隱碼注入)？

SQL Injection (SQLi) 是一種發生於應用程式與資料庫互動時的重大安全漏洞。當程式碼將**使用者未經過濾的輸入**直接以字串拼接的方式組合進 SQL 查詢語句時，攻擊者可以透過注入惡意的 SQL 語法碎片，藉此破壞原有的查詢邏輯，甚至控制整個資料庫。

⚠️ 核心致病原因

將「資料 (Data)」與「指令 (Code)」混淆。程式碼使用動態字串拼接（如 + 或 f-string），使傳入的資料被資料庫直譯器誤認為新的 SQL 關鍵字或結構。

💥 潛在危害風險

未授權繞過登入驗證、跨表竊取機密資料（機密性破壞）、隨意修改或刪除資料庫表格（完整性破壞），嚴重時可取得作業系統 Shell 權限。

🛡️ 根治解決方案

徹底放棄動態字串拼接！改採**預編譯參數化查詢 (Prepared Statements)**，將 SQL 語法結構事先編譯，讓輸入值永遠僅被當成純字串參數處裡。

常見 SQL Injection 攻擊型態

1. 身分驗證繞過 (In-band)

透過布林邏輯恆真（如 ' OR '1'='1）或註解符號（'--），使密碼比對邏輯失效直接登入。

2. UNION 跨表查詢 (In-band)

利用 UNION SELECT 將別的資料表（如 users, credit_cards）的結果強行附加在原本查詢輸出中。

3. 布林型盲注 (Boolean-Blind)

畫面不直接回傳資料，但可透過頁面回應是否正常（True/False），一步步逐字爆破逐字猜測。

4. 時間延遲型盲注 (Time-Blind)

頁面不顯示任何差異時，透過 SLEEP(3) 等函數強迫資料庫延遲回應，藉由 Response Time 推斷條件。

5. ORDER BY 動態排序

無法直接對 ORDER BY 進行參數化綁定，若直接拼接欄位名將造成極具威脅的盲注點，需用白名單防禦。

6. WAF 過濾與繞過

依賴簡單黑名單（過濾單詞）的 WAF 容易被大小寫混淆（oR）或註解（/**/）繞過，非根本解決之道。

          安全編碼規範：如何正確使用 Prepared Statements
        

        

          要完全防禦 SQL Injection，最有效的方法就是使用**參數化查詢 (Prepared Statements / Parameterized Queries)**。資料庫直譯器會先把 SQL 的語法結構編譯完畢，之後傳入的變數永遠只會被當成純字串（或資料值）處理，不會被直譯為指令。
        


        
        

          
          
          
          
        


        
        

          

            

              
❌ 危險寫法 (不安全的字串拼接)

              
# 絕不可以這樣寫！字串拼接會導致 SQLi
cursor.execute(
    f"SELECT * FROM users WHERE name = '{user_input}'"
)

            

            

              
✅ 安全寫法 (參數化查詢)

              
# 安全！使用 ? 佔位符並以 Tuple 傳入變數
cursor.execute(
    "SELECT * FROM users WHERE name = ?", 
    (user_input,)
)

            

          

        


        

          

            

              
❌ 危險寫法

              
const sql = `SELECT * FROM users WHERE name = '${userInput}'`;
db.query(sql);

            

            

              
✅ 安全寫法 (mysql2)

              
const sql = 'SELECT * FROM users WHERE name = ?';
db.execute(sql, [userInput]);

            

          

        


        

          

            

              
❌ 危險寫法

              
$sql = "SELECT * FROM users WHERE name = '" . $_GET['name'] . "'";
$pdo->query($sql);

            

            

              
✅ 安全寫法 (PHP PDO)

              
$stmt = $pdo->prepare('SELECT * FROM users WHERE name = :name');
$stmt->execute(['name' => $userInput]);

            

          

        


        

          

            

              
❌ 危險寫法

              
String sql = "SELECT * FROM users WHERE name = '" + input + "'";
Statement stmt = connection.createStatement();
stmt.executeQuery(sql);

            

            

              
✅ 安全寫法 (PreparedStatement)

              
String sql = "SELECT * FROM users WHERE name = ?";
PreparedStatement pstmt = connection.prepareStatement(sql);
pstmt.setString(1, input);
ResultSet rs = pstmt.executeQuery();

            

          

        


        
        

          
💡 特別陷阱：動態排序 ORDER BY 的防禦方式

          

            ORDER BY 的欄位名稱與排序方向（ASC/DESC）無法進行 SQL 參數化綁定。針對此類情況，絕對不可使用字串拼接，請務必採用後端白名單校驗 (Strict Whitelisting)：
          

          
allowed_columns = ["id", "username", "created_at"]
sort_column = input_col if input_col in allowed_columns else "id"
query = f"SELECT * FROM users ORDER BY {sort_column}"  # 已通過白名單校驗，安全！
