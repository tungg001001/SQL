什麼是 SQL Injection？

SQL Injection（SQL 隱碼注入）是一種常見的 Web 應用程式安全問題。當應用程式將使用者輸入直接拼接至 SQL 指令中，攻擊者可能影響原本 SQL 查詢的語意。 本網站使用「模擬資料庫」展示 SQL Injection 的基本原理， 不會連接真實資料庫。

經典情境

Auth Bypass

示範不安全字串拼接可能造成登入條件被改變。

UNION

UNION Injection

示範 UNION 查詢可能造成非預期資料被併入結果。

Blind SQLi

布林與時間盲注

SQL Injection 防禦

最重要的防禦方式是使用 Prepared Statements / Parameterized Queries。 其核心概念是將 SQL 結構與使用者輸入的資料分離。 


# ❌ 危險：字串串接
cursor.execute(
    f"SELECT * FROM users WHERE username = '{user_input}'"
)

# ✅ 安全：參數化查詢
cursor.execute(
    "SELECT * FROM users WHERE username = ?",
    (user_input,)
)
    

// ❌ 危險
const query =
  `SELECT * FROM users WHERE username = '${userInput}'`;

// ✅ 安全
const [rows] = await connection.execute(
  'SELECT * FROM users WHERE username = ?',
  [userInput]
);
    

// ❌ 危險
$db->query(
  "SELECT * FROM users WHERE username = '$userInput'"
);

// ✅ 安全
$stmt = $pdo->prepare(
  'SELECT * FROM users WHERE username = :user'
);

$stmt->execute([
  'user' => $userInput
]);
    

// ❌ 危險
Statement stmt = conn.createStatement();

stmt.executeQuery(
    "SELECT * FROM users WHERE username = '"
    + userInput + "'"
);

// ✅ 安全
PreparedStatement pstmt =
    conn.prepareStatement(
        "SELECT * FROM users WHERE username = ?"
    );

pstmt.setString(1, userInput);

ResultSet rs =
    pstmt.executeQuery();
⚠️ ORDER BY 特殊情境

欄位名稱通常不能直接使用 Prepared Statement 參數，因此應使用伺服器端白名單，例如只允許 id、username、role。
