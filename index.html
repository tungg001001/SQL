什麼是 SQL 隱碼注入 (SQL Injection)?

SQL Injection (SQLi) 是應用程式中最古老且最具破壞力的漏洞之一。當應用程式將「使用者輸入」直接字串串接（String Concatenation）進入 SQL 指令中，而未經過適當的驗證或轉義時，攻擊者就能輸入惡意的 SQL 語法片段，改變原資料庫查詢的邏輯結構，從而繞過身分驗證、讀取敏感資料或甚至竄改資料庫內容。

經典驗證繞過

Auth Bypass

透過注入 ' OR '1'='1 使帳號密碼條件判斷強制恆真，繞過登入驗證機制。

跨表資料竊取

UNION-Based Injection

利用 UNION SELECT 將原本查詢與別張敏感資料表的 SELECT 結果進行合併顯示。

無提示猜測萃取

Blind Injection (布林/時間)

系統不回傳錯誤訊息時，透過 True/False 頁面變化或 SLEEP() 延遲逐字爆破資料。

根治 SQL Injection 的黃金法則：預編譯 (Prepared Statements)

解決 SQL 注入最核心且唯一的徹底防禦手段是使用 預編譯查詢（Prepared Statements / Parameterized Queries）。預編譯會先將 SQL 語法結構發送給資料庫進行編譯，之後傳入的參數僅會被當作「純資料 (Scalar Values)」對待，完全失去改變 SQL 結構的能力。

# ❌ 危險寫法：直接字串串接 (Vulnerable) cursor.execute(f"SELECT * FROM users WHERE username = '{user_input}'") # ✅ 安全寫法：參數綁定 (Prepared Statement) cursor.execute("SELECT * FROM users WHERE username = %s", (user_input,))
// ❌ 危險寫法 const query = `SELECT * FROM users WHERE username = '${userInput}'`; // ✅ 安全寫法 (mysql2) const [rows] = await connection.execute( 'SELECT * FROM users WHERE username = ?', [userInput] );
// ❌ 危險寫法 $db->query("SELECT * FROM users WHERE username = '$userInput'"); // ✅ 安全寫法 (PDO) $stmt = $pdo->prepare('SELECT * FROM users WHERE username = :user'); $stmt->execute(['user' => $userInput]);
// ❌ 危險寫法 Statement stmt = conn.createStatement(); stmt.executeQuery("SELECT * FROM users WHERE username = '" + userInput + "'"); // ✅ 安全寫法 PreparedStatement pstmt = conn.prepareStatement("SELECT * FROM users WHERE username = ?"); pstmt.setString(1, userInput); ResultSet rs = pstmt.executeQuery();
⚠️ 特殊防禦情境：ORDER BY 與 COLUMN 名稱

`ORDER BY` 欄位名稱或 `ASC/DESC` 無法在 SQL 中直接使用佔位符 `?` 綁定。此類情況必須搭配 嚴格的伺服器端白名單驗證 (Whitelist Validation)，拒絕任何非預期欄位。
