Web Security Basics

什麽是 SQL Injection (SQL 注入漏洞)？

SQL Injection 是最經典且危害極大的 Web 安全漏洞之一。當應用程式將「未經過濾的使用者輸入」直接串接到 SQL 查詢字串中執行時，攻擊者可藉由構造特殊的 SQL 語法改變原本查詢邏輯，進而取得未授權資料、修改資料庫，甚至接管伺服器。

1. 身份驗證繞過

透過構造如 ' OR '1'='1 的條件，使 WHERE 子句恆為真（True），藉此跳過密碼驗證以任意使用者身份登入。

2. UNION 竊取資料

利用 UNION SELECT 將原查詢結果與自訂查詢結果合併，進而讀取資料庫中其他敏感資料表（如 user_passwords）。

3. 盲注 (Blind SQLi)

網頁不直接回傳資料庫內容時，透過發送條件判斷句（Boolean-based）或時間延遲（Time-based, 例如 SLEEP(5)），逐字推算內部資料。

漏洞防範防線：參數化查詢 (Prepared Statements)

防範 SQL Injection 最有效的方式是使用參數化查詢（Prepared Statements / Parameterized Queries）。資料庫會先編譯 SQL 指令結構，再將使用者輸入當作純粹的「資料值」帶入，徹底隔絕語法被注入的可能。 

# ❌ 錯誤寫法 (高危險：字串串接)
cursor.execute(f"SELECT * FROM users WHERE username = '{username}' AND password = '{password}'")

# ✅ 安全寫法 (使用佔位符 ?)
cursor.execute("SELECT * FROM users WHERE username = ? AND password = ?", (username, password))
// ❌ 錯誤寫法
const query = `SELECT * FROM users WHERE email = '${req.body.email}'`;

// ✅ 安全寫法 (mysql2 預備語法)
const [rows] = await db.execute(
  'SELECT * FROM users WHERE email = ?',
  [req.body.email]
);
// ❌ 錯誤寫法
$sql = "SELECT * FROM users WHERE id = " . $_GET['id'];

// ✅ 安全寫法 (PDO Prepared Statement)
$stmt = $pdo->prepare('SELECT * FROM users WHERE id = :id');
$stmt->execute(['id' => $_GET['id']]);
$user = $stmt->fetch();
// ❌ 錯誤寫法
String sql = "SELECT * FROM users WHERE username = '" + user + "'";

// ✅ 安全寫法 (PreparedStatement)
String sql = "SELECT * FROM users WHERE username = ?";
PreparedStatement pstmt = conn.prepareStatement(sql);
pstmt.setString(1, user);
ResultSet rs = pstmt.executeQuery();
